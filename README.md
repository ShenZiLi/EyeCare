EyeCare is a desktop break reminder that lives in your system tray, built for macOS, Windows, and Linux. It reminds you to rest based on mouse or keyboard activity, or at fixed intervals. Settings save automatically, and configuration and timing are handled locally.

The project is under active development. The current version is **1.0.2**. No installer is currently available through GitHub Releases; you can run from source or build a package locally. See [Platform support](#platform-support) for the scope of testing on each platform.

[Quick start](#quick-start) · [Usage](#usage) · [Local packaging](#local-packaging) · [FAQ](#faq) · [Contributing](#contributing)

## Features

- **Two timing modes**: accumulate active mouse or keyboard time, or receive reminders at fixed intervals.
- **Four reminder types**: a gentle screen fade, an acknowledgment overlay, a system notification, or sound only. Visual reminders can also play a sound.
- **Automatic away detection**: extended idle time resets progress. Locking, sleep, or a failure in a critical system check suppresses new reminders; missed reminders are not replayed on return.
- **System tray integration**: a countdown and menu actions for pausing, resuming, triggering a reminder, opening settings, and quitting.
- **Manual pause**: reminders stay paused until you choose to resume.
- **Instant settings**: eight core options that save automatically.
- **Light and dark themes**: light, dark, and system appearance in a compact Liquid Glass interface.
- **System preferences**: automatically respects preferences such as reduced motion and reduced transparency.

## Quick start

### Requirements

- Node.js **24**. The repository's build workflow uses **24.15.0**.
- npm **11**.
- Git and an active desktop session on your operating system.

Dependency versions are locked in [package-lock.json](package-lock.json). Run and package the app on the target platform; see the support details below.

### Run from source

```bash
git clone https://github.com/ShenZiLi/EyeCare.git
cd EyeCare
npm ci
npm start
```

`npm start` launches the Electron development app and a local Vite server. System notifications on macOS require a fully signed app bundle. To test notifications, use the `.app` generated by `npm run make`.

If your terminal has `ELECTRON_RUN_AS_NODE` set, unset it first; otherwise, Electron will run as a Node.js process.

## Usage

1. Choose a timing mode and duration under Trigger conditions (触发条件).
2. Choose a visual reminder type and sound setting under Reminder type (提醒方式). Use Preview (预览效果) to try the reminder.
3. Close the main window to keep EyeCare running in the tray, and click the tray icon to open its menu. Choose Quit EyeCare (退出 EyeCare) to stop the app. In environments without a reliable system tray, the main window remains accessible.

Settings save automatically. Numeric inputs save about 300 milliseconds after you stop typing, or when the field loses focus. Invalid values or save failures show an explanation and leave the previous valid configuration in place. Restoring defaults requires confirmation.

### Core settings

| Page | Setting | Default | Options / range |
| --- | --- | --- | --- |
| Trigger conditions | Timing mode | Accumulated active time | Accumulated active time / Fixed interval |
| Trigger conditions | Reminder time | 30 minutes | Whole numbers from 1–240 minutes |
| Trigger conditions | Idle reset threshold | 10 minutes | Whole numbers from 1–120 minutes; shown in accumulated active time mode |
| Reminder type | Primary visual mode | Gentle screen fade | Gentle screen fade / Acknowledgment overlay / System notification / Sound only |
| Reminder type | Enable reminder sound | Off | On / Off |
| General settings | Theme | System | System / Light / Dark |
| General settings | Tray countdown | On | On / Off |
| General settings | Launch at login | Off | On / Off |

The reminder time is labeled Active reminder time (活跃提醒时间) in accumulated active time mode and Interval (间隔时间) in fixed interval mode. Choosing Sound only automatically enables sound, so the sole reminder channel cannot be disabled. The default window size is **600 × 620** logical pixels. Narrow windows use icon navigation; hover over a button to see its page name.

### Timing and reminder rules

| Scenario | Behavior |
| --- | --- |
| Accumulated active time | Any mouse or keyboard activity maintains a fixed 60-second activity window; accumulation pauses outside that window |
| Fixed interval | Reminds at the configured interval; cycles suppressed by locking, sleep, manual pause, or similar states are skipped |
| Idle reset threshold reached | Resets progress and stops new reminders; progress also resets during manual pause |
| Gentle screen fade | A full-screen black overlay fades in, holds, and fades out over about 2 seconds, reaching 90% opacity; it does not take focus and allows clicks through |
| Acknowledgment overlay: Got it (知道了) | Closes all associated overlays, records a confirmed break, resets progress, and starts the next cycle |
| Close overlay / Escape | Skips the current cycle and starts the next one without recording a confirmed break |
| Notification submitted / Sound finished | Automatically ends the current cycle without recording a confirmed break |
| Preview | Does not affect actual timing progress or break confirmations |

Reminders cover all displays. Sound uses a built-in gentle effect at a fixed 50% volume. The activity window, effect parameters, wording, sound, and display coverage follow fixed conventions. Advanced configuration and snoozing are not available.

## Platform support

The table distinguishes support targets from evidence collected on real devices. Framework support or a successful build does not constitute full platform acceptance.

| Platform | Support target | Current verification |
| --- | --- | --- |
| macOS | 14+, Apple Silicon / Intel | Native timing, input, packaging, tray, and reminders verified on macOS 26.4 ARM64; notification submission verified with a locally signed bundle. Intel, other OS versions, and some physical scenarios remain unverified |
| Windows | Windows 11 x64 | Installation, upgrades, launch paths, native timing, and reminder cycles verified; some physical scenarios remain unverified |
| Linux X11 | Ubuntu 24.04 GNOME, KDE 6, x64 | Adapters and packaging configuration implemented; no acceptance records from a real Linux device yet |
| Linux Wayland | Desktop capabilities are limited | Session-wide input detection, positioning, and full-screen coverage have not been reliably verified; full support cannot be claimed |

For progress on physical locking, sleep, multiple displays, virtual desktops, login startup, and extended runtime, see the [acceptance records](docs/acceptance.md) and [native capability evidence](docs/platform-evidence.md).

## Local packaging

```bash
# Generate the application directory for the current platform
npm run package

# Generate installers or archives for the current platform
npm run make
```

Application directories are written to `out/`, and distribution artifacts to `out/make/`.

| Platform | Artifacts |
| --- | --- |
| macOS | `.app` application directory, ZIP |
| Windows | Squirrel installer, ZIP |
| Linux x64 | deb, rpm, ZIP, AppImage |

Linux builds require `fakeroot`, `rpm`, and `appimagetool`; the current workflow uses appimagetool 1.9.1. Desktop runtime dependencies include GTK3, NSS, XScreenSaver, audio libraries, and session D-Bus. AppImage retains the Chromium sandbox, so the target environment must support the corresponding sandbox mechanism. See the [build workflow](.github/workflows/build.yml) for dependency installation examples.

### Signing and releases

When no Developer ID is configured on macOS, local packaging applies an **ad-hoc signature** to the complete app. This supports local execution and notification submission checks; it does not replace Developer ID signing and notarization.

| Purpose | Build environment variables |
| --- | --- |
| macOS Developer ID signing | `EYECARE_SIGN_IDENTITY` |
| macOS notarization, in addition to signing | `EYECARE_APPLE_ID`, `EYECARE_APPLE_PASSWORD`, `EYECARE_APPLE_TEAM` |
| Windows installer signing | `EYECARE_WINDOWS_CERT_FILE`, `EYECARE_WINDOWS_CERT_PASSWORD` |

Provide credentials through your local environment or CI, and keep them out of the repository. Windows artifacts do not carry the corresponding release signature when no Windows certificate is configured.

The [GitHub Actions workflow](.github/workflows/build.yml) checks and builds on Windows, macOS ARM64 / Intel, and Ubuntu, then uploads the outputs as workflow artifacts. It does not automatically publish a Release.

## Development and verification

Stack: **Electron 44 · React 19 · TypeScript · Vite · Electron Forge · Koffi**.

```bash
# Type checking, linting, unit tests, and integration tests
npm run check

# Build the latest main process and pages, then run real Electron UI tests
npm run package
npm run test:e2e
```

You can also run `npm run typecheck`, `npm run lint`, `npm run test:unit`, and `npm run test:integration` separately. UI tests use a temporary configuration directory and do not replace native platform acceptance testing.

### Native checks

| Command | Purpose |
| --- | --- |
| `npm run probe:platform` | Read-only checks of the current platform's clock, input, and session state |
| `npm run verify:macos-runtime` | Native Mac checks covering a one-minute cycle, hidden window, tray, and overlay acknowledgment |
| `npm run verify:windows-runtime` | Native Windows checks covering two one-minute cycles, hidden window, and reminder cleanup |

Cycle checks display actual screen fades or overlays. They use isolated configuration and do not change user preferences, login items, or notification permissions. Results are written to the corresponding runtime evidence files in `docs/`.

### Project structure

```text
EyeCare/
├── app/
│   ├── main/        # Timing, platform observation, settings persistence, reminders, and tray
│   ├── preload/     # Restricted IPC bridge
│   ├── renderer/    # React settings pages and reminder UI
│   └── shared/      # Shared types, fixed defaults, and settings validation
├── resources/       # Icons and built-in resources
├── scripts/         # Build tools and native verification scripts
├── tests/           # Unit, integration, and Electron UI tests
├── docs/            # Platform evidence, acceptance records, and screenshots
├── design-system/   # UI design guidelines
└── .github/         # Cross-platform checks and build workflows
```

The main process exclusively owns timing and reminder state. Pages handle display and settings input. Timing does not depend on page timers, so the app can keep running in the tray after the window closes.

## Privacy and configuration

- EyeCare does not collect keystroke content, mouse trajectories, or screen images. It uses only system activity and idle state for timing.
- Settings are stored in `settings.json` in Electron's `userData` application directory.
- The last valid configuration is backed up as `settings.last-good.json`. Before upgrading a valid legacy configuration, the original file is preserved as `settings.v1-backup.json`.
- Upgrades from older versions preserve the eight core choices; legacy advanced parameters no longer affect runtime behavior.
- Restarting restores settings and starts a new cycle. Reminders missed while the app was closed are not replayed.

## FAQ

### What should I do if macOS system notifications fail?

Use the signed `.app` generated by `npm run make`. If notifications are reported as disallowed, check System Settings → Notifications → EyeCare → Allow Notifications. When the system first asks for permission, the user must choose whether to allow it.

Successful submission does not guarantee an immediate banner. System settings such as Focus and screen sharing can also affect presentation. See the [official Electron documentation](https://www.electronjs.org/docs/latest/api/notification) for notification signing requirements.

### Why has time accumulation or a reminder stopped?

Accumulated active time mode pauses accumulation after the 60-second activity window expires. Manual pause, locking, sleep, extended idle time, or an unconfirmed critical system state suppresses new reminders. After a manual pause, choose Resume reminders (恢复提醒) to continue.

### Why did launch at login not take effect?

Check the app's save error message and your system's login item settings first. If registration or saving fails, the app keeps the previous valid configuration and attempts to restore the prior system state. You can retry in the app.

### The build succeeded. Where is the complete app?

Check both the application in `out/` and the distribution artifacts in `out/make/`, rather than relying on the command's exit status alone. The repository pins an override for the extraction dependency used by `@electron/packager`: `@electron-internal/extract-zip@1.0.5`, which requires Node ≥22.12. Use the repository's specified Node 24 version.
